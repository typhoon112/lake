## 二、关键问题修复（2026-03-27 ~ 2026-03-28）

### 2.1 同日多 Granule 水位不一致问题 ✅ 已修复（2026-03-27）

**问题描述**：同一湖泊同一天多个 granule 的水位值不一致，差异可达 83m。

**根本原因**：
1. 同一 Pass 的多个 Scene 被逐个独立处理
2. 没有进行空间拼接就直接按湖泊裁切
3. 每个处理都产生独立记录，导致重复

**解决方案**：
重构 `process_time_group` 方法，采用 **"先 QC 后拼接"** 策略：

```
处理流程：
1. 收集 QC 前统计（原始数据）
2. 逐个 granule 独立进行 QC（坏像元 → NaN）
3. 空间拼接所有 QC 后的 granule
   - wse: 不确定度加权平均
   - wse_uncert: RSS 合并
   - 其他变量: 算术平均
4. 收集拼接后统计
5. 输出三阶段对比日志
6. 遍历湖泊裁切 → 每个湖泊只产生一条记录
```

**修改文件**：
- `src/process/main.py` - 重构 `process_time_group`，新增 `_merge_wse_weighted` 和 `_merge_with_average` 方法
- `src/process/timeseries.py` - `wse` 字段改为不确定度加权平均

### 2.2 WSE 聚合方法（2026-04-11 更新）

**所有聚合层统一使用不确定度加权平均**：

1. **Merge 阶段**：多个 granule 重叠区的 wse 用 `1/σ²` 加权平均
```python
# _merge_wse_weighted: 一次遍历同时计算
wse_merged = Σ(wse_i / σ²_i) / Σ(1/σ²_i)
σ_merged = 1 / √(Σ(1/σ²_i))
```

2. **湖泊聚合阶段**：裁切后的多像素聚合到单个值也用加权平均
```python
wse = Σ(wse_i / σ²_i) / Σ(1/σ²_i)
```

**变更点**：
- `wse_weighted` 字段已移除，`wse` 本身就是加权平均值
- 新增 `wse_med`（中位数）作为备用字段
- `wse_std` 与加权平均使用相同的像元子集

### 2.3 配置统一（2026-04-11 新增）

**settings.py 为唯一配置来源**：
- `QualityConfig` 去掉了默认值，变为必填字段
- `QualityController` 默认从 `settings.py` 的 `QUALITY_CONFIG` 读取
- 消除了配置双重定义的风险

### 2.5 分布式计算架构 ✅ 新增（2026-03-28）

**功能**：支持分阶段处理，便于分布式计算

**命令**：
```bash
# 阶段一：QC + 拼接 → 输出中间影像
python -m src.process.main --prior data/prior/QB58_716_4.shp --stage merge

# 阶段二：湖泊裁切 + WSE 计算
python -m src.process.main --prior data/prior/QB58_716_4.shp --stage clip
```

**新增方法**：
| 方法 | 功能 |
|------|------|
| `merge_time_group()` | 阶段一：QC + 拼接 + 输出中间影像 |
| `clip_lakes_from_merged()` | 阶段二：湖泊裁切 + WSE 计算 |
| `run_stage1()` | 阶段一入口 |
| `run_stage2()` | 阶段二入口 |
| `_export_merged_raster()` | 导出中间影像 |
| `_load_merged_raster()` | 读取中间影像 |

**输出结构**：
```
output/merged/           # 阶段一输出
├── 037_467_PID0.tif    # 拼接后的影像
└── 037_467_PID0.json   # 元数据
```
