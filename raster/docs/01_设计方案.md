# SWOT 湖泊时序数据提取 - 设计方案

## 一、项目背景与目标

### 核心研究目标

**最终目的**：重建湖泊水下地形（Lake Bathymetry）

**技术路线**：
```
SWOT L2_HR_Raster 时序观测
    ↓
不同水位时刻的湖岸线（等高线）
    ↓
多条不同水位的等高线
    ↓
空间插值重建水下地形
```

这种方法利用湖泊水位的季节性/年际变化，将每个水位时刻的岸线视为一条"等高线"，通过多条等高线插值重建湖底地形。

### 研究需求
1. 使用自定义的湖泊群先验 shp 数据
2. 下载 SWOT L2_HR_Raster 栅格数据
3. 用 shp 裁切栅格数据，提取研究湖泊群的时序水位数据
4. 生成带有空间特征的等高岸线（矢量数据）
5. 输出用于后续地形重建的完整数据集

### 数据产出说明

| 产出类型 | 用途 | 说明 |
|----------|------|------|
| `lake_timeseries.csv` | 时序汇总 | 每条岸线对应的水位值、面积、时间 |
| `*_wse.tif` | 水位栅格 | 该时刻的水位空间分布 |
| `*_contour.shp` | 等高岸线 | 从水位栅格提取的湖岸线矢量 |

### 关键数据质量指标

1. **水位变化范围**：
   - 范围越大 → 等高线覆盖越广 → 地形重建效果越好
   - 警惕：水位范围 < 1m 的湖泊，岸线堆积，难以重建地形

2. **岸线数量**：
   - 时序观测越多 → 等高线越密集 → 地形分辨率越高

3. **空间一致性**（**核心要求**）：
   - 同一湖泊同一天多个 granule 的水位应一致
   - 若不一致，说明空间聚合存在问题（可能是先验边界包含多个独立水体）

## 二、SWOT 轨道与分组说明

### 2.1 SWOT 轨道特点

| 参数 | 值 | 说明 |
|------|-----|------|
| 轨道周期 | 21 天 | 完整覆盖周期 |
| 轨道间距 | ~1.4°（赤道） | 相邻 Pass 经度间隔 |
| Pass 宽度 | ~50 km | 单个 Pass 覆盖宽度 |
| Scene 大小 | 128×128 km | 单个 Scene 覆盖范围 |
| Scene 重叠 | 25-30 km | 同一 Pass 内相邻 Scene 沿轨重叠 |

### 2.2 分组逻辑

**分组 ID**: `cycle_pass_crid`

```python
group_id = f"{cycle}_{pass}_{crid}"
# 示例: 037_467_PID0
```

| 字段 | 说明 | 决定 |
|------|------|------|
| `cycle` | 轨道周期 | 时间（~21天一周期） |
| `pass` | 轨道编号 | **经度**（决定覆盖区域） |
| `crid` | 数据版本 | PID0=D版, PIC2=C版 |
| `scene` | 场景标识 | 纬度（**分组内**，用于拼接） |

### 2.3 为什么不同 Pass 不合并？

```
同一日期的 Pass 覆盖示意：

日期 2025-08-27:
  ┌────────────────────────────────────────────┐
  │           研究区 (90-99°E)                  │
  │                                            │
  │   Pass 217        Pass 189        Pass 467 │
  │   ┌────────┐     ┌────────┐     ┌────────┐│
  │   │ 湖泊A  │     │ 湖泊B  │     │ 湖泊C  ││
  │   │ 湖泊D  │     │ 湖泊E  │     │        ││
  │   └────────┘     └────────┘     └────────┘│
  │   90-92°E        90-95°E        91-96°E  │
  └────────────────────────────────────────────┘

关键点:
- 不同 Pass 覆盖不同经度带
- 每个湖泊通常只被 1 个 Pass 观测
- 不需要合并不同 Pass 的数据
```

### 3.2 关键设计决策

#### 决策 1：空间重叠检查在 QC 之前（重要优化）

**位置**：`check_spatial_overlap()` 方法

**时机**：
1. **阶段 1（收集 QC 前统计）**：在读取数据后立即检查
2. **阶段 2（逐个 Granule QC）**：在读取数据后、QC 之前检查

**目的**：
- 提前过滤不覆盖研究区的 granule
- 避免对无效数据进行耗时的 QC 操作
- 大幅减少计算量和内存使用

**实现逻辑**：
```python
def check_spatial_overlap(self, ds, prior_gdf) -> bool:
    # 1. 提取数据集的经纬度范围
    lon = ds['longitude'].values
    lat = ds['latitude'].values
    data_bounds = (lon.min(), lat.min(), lon.max(), lat.max())

    # 2. 获取先验边界范围
    prior_bounds = gdf_to_bounds(prior_gdf)

    # 3. 检查边界框是否重叠
    return bounds_overlap(data_bounds, prior_bounds)
```

**效果**：
- 1947 个时间组中，仅 582 个（约 30%）覆盖研究区
- 70% 的数据在 QC 之前被过滤，大幅提升效率

---

#### 决策 2：先 QC 后拼接

| 方案 | 问题 |
|------|------|
| 先拼接后 QC | 重叠区的质量标志不一致，难以判断哪个像元有效 |
| **先 QC 后拼接** ✅ | 每个像元独立判断质量，坏像元设为 NaN，拼接时只累加有效值 |

```
先 QC 后拼接示意：
  Scene 1: [good, bad, good]  →  QC  →  [1.2, NaN, 1.3]
  Scene 2: [good, good, good] →  QC  →  [1.1, 1.2, 1.4]
                                    ↓ 拼接（重叠区平均）
                              [1.15, 1.2, 1.35]
```

## 四、质量控制标准（核心）

### 4.1 质量控制流程

质量控制按以下顺序执行（5 个过滤条件）：

```python
def _create_quality_mask(self, ds):
    mask = np.ones(shape, dtype=bool)  # 初始化为全 True

    # 1. WSE 质量过滤
    mask = self._filter_by_wse_qual(ds, mask)

    # 2. cross_track 过滤
    mask = self._filter_by_cross_track(ds, mask)

    # 3. 水体比例过滤
    mask = self._filter_by_water_frac(ds, mask)

    # 4. 冰期过滤（可选，D 版本跳过）
    if not self.config.skip_ice_filter:
        mask = self._filter_by_ice_flags(ds, mask)

    # 5. 不确定度过滤
    mask = self._filter_by_uncertainty(ds, mask)

    return mask
```

### 4.2 各过滤条件详解

| 序号 | 过滤条件 | 代码实现 | 阈值 |
|------|----------|----------|------|
| 1 | WSE 质量 | `wse_qual <= 1` | 保留 good/suspect |
| 2 | cross_track | `abs(cross_track) > 10000` | 排除近 nadir 伪影 |
| 3 | 水体比例 | `water_frac >= 0.3` | 水体比例阈值 |
| 4 | 冰期过滤 | `ice_clim_flag in [0, -999]` | D 版本跳过 |
| 5 | 不确定度 | `wse_uncert <= 10.0` | 最大不确定度 |

**代码实现**：
```python
# _filter_by_wse_qual: 水位质量
wse_qual = ds['wse_qual'].values
valid_qual = (wse_qual <= 1) & (wse_qual >= 0)

# _filter_by_cross_track: 近 nadir 伪影
cross_track = ds['cross_track'].values
valid_track = np.abs(cross_track) > 10000

# _filter_by_water_frac: 水体比例
water_frac = ds['water_frac'].values
valid_frac = (water_frac >= 0.3) & (water_frac <= 1.0)

# _filter_by_ice_flags: 冰期（可选）
ice_clim = ds['ice_clim_flag'].values
ice_dyn = ds['ice_dyn_flag'].values
valid_ice = (ice_clim == 0) | (ice_clim == -999)
valid_ice = valid_ice & ((ice_dyn == 0) | (ice_dyn == -999))

# _filter_by_uncertainty: 不确定度
wse_uncert = ds['wse_uncert'].values
valid_uncert = (wse_uncert <= 10.0) & (wse_uncert < 1e10)
```

### 4.3 过滤后的数据处理

**坏像元处理**：设为 NaN，而非删除
```python
# 应用质量掩码，坏像元变为 NaN
ds_filtered = ds.copy()
wse = ds_filtered['wse'].values
wse[~quality_mask] = np.nan  # 坏像元设为 NaN
```

**好处**：
- 保持数据形状不变，便于拼接
- NaN 自动参与计算，不影响有效值统计

### 5.2 WSE 聚合方法

**所有聚合层均使用不确定度加权平均**（统计最优）：

1. **Merge 阶段**（多个 granule 重叠区 → 单个像素）：
```python
# wse = Σ(wse_i / σ²_i) / Σ(1/σ²_i)
# σ_merged = 1 / √(Σ(1/σ²_i))
```

2. **湖泊聚合阶段**（多个像素 → 单个湖泊值）：
```python
# 权重 = 1 / σ²
weights = 1.0 / (wse_uncert ** 2)
wse = np.nansum(wse_values * weights) / np.nansum(weights)
wse_uncert_combined = np.sqrt(1.0 / np.nansum(weights))
```

**中位数作为备用**：
```python
wse_median = np.nanmedian(wse_values)
```

**输出字段**：
| 字段 | 说明 | 主要/备用 |
|------|------|----------|
| `wse` | 不确定度加权平均 | **主要** |
| `wse_med` | 中位数 | 备用 |
| `wse_uncert` | 合并不确定度 | - |

### 5.3 空间裁切实现

```python
def clip_to_lake(self, ds, lake_id, id_column):
    # 1. 获取湖泊几何
    lake_geom = prior_gdf[prior_gdf[id_column] == lake_id].geometry.iloc[0]

    # 2. 转换坐标系（如果需要）
    if ds.rio.crs != prior_gdf.crs:
        lake_geom = lake_geom.to_crs(ds.rio.crs)

    # 3. 使用 rioxarray 裁切
    try:
        ds_clipped = ds.rio.clip([lake_geom], lake_geom.crs)
    except:
        # 备用：手动裁切
        ds_clipped = self._clip_manual(ds, lake_geom)

    return ds_clipped, clip_stats
```

## 七、空间拼接方法

### 10.1 架构设计

将处理流程拆分为两个独立阶段，支持分布式计算：

```
阶段一: merge_time_group() → QC + 拼接 → 输出中间影像 (TIFF)
阶段二: clip_lakes_from_merged() → 读取中间影像 → 裁切 → WSE计算
```

### 10.2 处理流程

```
SWOTRasterProcessor
├── merge_time_group()           # 阶段一：QC + 拼接 + 输出中间影像
│   ├── 阶段1: 收集 QC 前统计
│   ├── 阶段2: 逐个 granule 进行 QC
│   ├── 阶段3: 空间拼接（重叠区取平均）
│   ├── 阶段4-5: 统计和日志
│   └── 阶段6: 输出中间影像 (TIFF)
│
├── clip_lakes_from_merged()     # 阶段二：湖泊裁切 + WSE 计算
│   └── 遍历湖泊裁切 + 输出
│
├── run_stage1()                 # 阶段一入口：仅拼接
├── run_stage2()                 # 阶段二入口：仅裁切
└── run()                        # 原有入口：两阶段连续执行
```

### 10.3 输出结构

```
output/
├── merged/                      # 阶段一输出
│   ├── 037_467_PID0.tif        # 拼接后多波段影像 (wse, water_frac, wse_uncert)
│   ├── 037_467_PID0.json       # 元数据 (group_id, date)
│   └── ...
├── <lake_id>/                   # 阶段二输出
│   ├── rasters/
│   └── vectors/
└── summary/
    ├── lake_timeseries.csv
    └── statistics.json
```

### 10.4 分布式优势

1. **阶段一可并行**：不同时间组可分配到不同节点
2. **阶段二可并行**：不同湖泊可分配到不同节点
3. **中间结果持久化**：中断后可从阶段二继续
4. **职责分离**：拼接和裁切完全独立

## 八、运行命令

### 11.1 完整处理（一次性运行）

```bash
cd /data/lyf/geo/Lake

# 激活环境
conda activate py10

# 完整运行
python -m src.process.main --prior data/prior/QB58_716_4.shp

# 测试模式 (处理 3 个时间组)
python -m src.process.main --prior data/prior/QB58_716_4.shp --test

# 限制处理数量
python -m src.process.main --prior data/prior/QB58_716_4.shp --max-files 10
```

### 11.2 分布式处理（分阶段运行）

```bash
# 阶段一：QC + 拼接，输出中间影像
python -m src.process.main --prior data/prior/QB58_716_4.shp --stage merge

# 阶段二：湖泊裁切 + WSE 计算
python -m src.process.main --prior data/prior/QB58_716_4.shp --stage clip
```

### 11.3 命令行参数

| 参数 | 简写 | 默认值 | 说明 |
|------|------|--------|------|
| `--prior` | `-p` | 必填 | 先验湖泊边界 Shapefile 路径 |
| `--raster` | `-r` | 配置路径 | Raster 数据目录 |
| `--output` | `-o` | 配置路径 | 输出目录 |
| `--stage` | `-s` | `all` | 处理阶段：`all`/`merge`/`clip` |
| `--max-files` | `-m` | 无 | 最大处理文件数 |
| `--test` | `-t` | False | 测试模式 |
