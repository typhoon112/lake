### 1.1 WSE 聚合统一 & 配置统一（2026-04-11 更新）

**问题描述**:
1. WSE 聚合方式不统一：merge 阶段和湖泊聚合阶段使用了不同的聚合方法
2. `QualityConfig` 有独立默认值，与 `settings.py` 中的 `QUALITY_CONFIG` 可能不一致
3. `wse_weighted` 字段冗余：既然 wse 应统一为加权平均，就不需要单独的 `wse_weighted` 字段

**解决方案**:

**1. WSE 聚合统一为不确定度加权平均**：

所有聚合层使用相同的公式：`wse = Σ(wse_i/σ²_i) / Σ(1/σ²_i)`

- **Merge 阶段**：`_merge_wse_weighted()` 方法，一次遍历同时计算 wse 加权平均和 uncert RSS
  ```python
  # wse_merged = Σ(wse_i / σ²_i) / Σ(1/σ²_i)
  # σ_merged = 1 / √(Σ(1/σ²_i))
  ```
- **湖泊聚合阶段**：`calculate_wse_statistics()` 也使用 `1/σ²` 加权平均
  ```python
  weights = 1.0 / (wse_uncert ** 2)
  wse = np.nansum(wse_values * weights) / np.nansum(weights)
  wse_uncert_combined = np.sqrt(1.0 / np.nansum(weights))
  ```

**2. 配置统一**：
- `QualityConfig` 去掉默认值，变为必填字段
- `QualityController` 默认从 `settings.py` 的 `QUALITY_CONFIG` 读取
- 消除了配置双重定义的风险

**3. 字段调整**：
- `wse` 字段直接就是不确定度加权平均值（主要值）
- 新增 `wse_med`（中位数）作为备用字段
- `wse_std` 基于与加权平均相同的像元子集计算（一致性）

**修改文件**：
- `src/process/main.py` — 新增 `_merge_wse_weighted()` 方法，简化 `_merge_with_average()`
- `src/process/timeseries.py` — `calculate_wse_statistics()` 统一使用加权平均
- `src/process/quality_control.py` — `QualityConfig` 必填化，`QualityController` 从 settings 读取

**经验教训**：
- 统计最优方法应在所有聚合层保持一致
- 配置参数应有唯一定义来源，避免双重定义
- 简化方法设计（去掉多模式参数），单一职责更清晰

### 1.1 统一投影转换（2026-03-29 新增）

**问题描述**:
验证脚本发现约 53% 的时间组内存在不同 UTM Zone 的 granule。原代码假设所有 granule 使用相同 CRS，直接拼接会导致坐标错位。

**根本原因**:
- SWOT Raster 的 pass 决定经度覆盖范围
- 一条 pass 可能跨越 UTM zone 边界（每 6° 一个 zone）

```python

                             target_crs: str = "EPSG:32646") -> xr.Dataset:
    """将数据集投影转换到目标 CRS"""
    # 1. 获取原始 CRS
    # 2. 检查是否需要转换
    # 3. 使用 rioxarray 的 reproject 方法转换
    # 4. 返回转换后的数据集

# main.py - merge_time_group() 中新增调用
ds = self.preprocessor.fill_to_nan(ds)
ds = self.preprocessor.reproject_to_target_crs(ds, TARGET_CRS)  # 新增
ds_qc, qc_stats = self.quality_controller.apply_quality_filter(ds)
```

**投影选择依据**:
- 先验湖泊边界 (SHP) 使用 EPSG:32646
- UTM Zone 46N 中央经线 93°E，与研究区 (89°-96°E) 匹配
- 面积误差 < 0.3%，满足精度要求

**验证方法**:
```bash
# 检查投影一致性
python -m src.utils.check_projection --dir data/raw --sample-groups 30
```

**经验教训**:
- 拼接前必须确保所有 granule 使用相同投影
- 不能假设同一时间组的 CRS 一致，需要验证
- rioxarray 的 reproject 方法可处理投影转换

### 1.2 同日多 Granule 水位不一致（2026-03-27 修复）

**问题描述**:
同一湖泊同一天出现多条水位记录，且水位差异可达 83m。

**根本原因**:
1. 同一 Pass 的多个 Scene 被逐个独立处理
2. 没有进行空间拼接就直接按湖泊裁切
3. 每个处理都产生独立记录，导致重复

**解决方案**:
重构 `process_time_group` 方法，采用 **"先 QC 后拼接"** 策略：

```python
def process_time_group(self, group_id, granule_paths, prior_gdf):
    # 阶段1: 收集 QC 前统计
    pre_qc_stats = self._collect_granule_stats(granule_paths, prior_gdf, stage='raw')

    # 阶段2: 逐个 granule 进行 QC（坏像元变为 NaN）
    qc_filtered_datasets = []
    for granule_path in granule_paths:
        ds_qc, qc_stats = self.quality_controller.apply_quality_filter(ds)
        qc_filtered_datasets.append(ds_qc)

    # 阶段3: 空间拼接（重叠区取平均）
    ds_merged = self._merge_qc_datasets(qc_filtered_datasets)

    # 阶段4-5: 统计和日志
    # 阶段6: 遍历湖泊裁切 → 每个湖泊只产生一条记录
```

**空间拼接方法**:
相邻 Scene 有 25-30km 沿轨重叠，使用平均值处理：
```python
def _merge_with_average(self, arrays):
    """重叠区取平均"""
    out_sum = np.zeros((height, width))
    out_count = np.zeros((height, width))

    for arr in arrays:
        # 累加有效值，计数
        valid = ~np.isnan(val) & (val < 9e36)
        out_sum[valid] += val
        out_count[valid] += 1

    # 计算平均值
    out_avg = np.where(out_count > 0, out_sum / out_count, np.nan)
```

**经验教训**:
- 同一时刻的相邻 Scene 有重叠，必须先拼接再裁切
- 拼接应在 QC 后进行，避免质量标志的歧义
- 每个湖泊每天只应产生一条记录

### 1.3 合并后 CRS 冲突（2026-03-27 修复）

**问题描述**:
合并多个数据集后出现 `Multiple grid mappings exist` 错误。

**根本原因**:
每个原始数据集都有自己的 `crs` 变量，复制其他变量时也复制了旧的 `grid_mapping` 属性。

**解决方案**:
```python
# 复制变量时清除旧的 grid_mapping 属性
for var in ['wse_uncert', 'latitude', 'longitude', ...]:
    merged[var] = datasets[0][var].copy()
    if 'grid_mapping' in merged[var].attrs:
        del merged[var].attrs['grid_mapping']

# 写入唯一的 CRS
merged = merged.rio.write_crs(crs_to_use, inplace=False)
```

**经验教训**:
- 合并数据集时需要清理旧的 CRS 相关变量
- 使用 rioxarray 的 `write_crs` 方法写入唯一的 CRS

### 1.4 CRS 坐标系处理

**问题描述**:
`spatial_clip.py` 中的 `_get_dataset_crs()` 方法无法获取数据集的 CRS 信息，返回 `None`，导致空间裁切失败。

**根本原因**:
`preprocess.py` 的 `read_granule()` 方法在读取变量时，没有包含 `crs` 和 `spatial_ref` 变量，导致这些坐标系信息被丢弃。

**解决方案**:
```python
# preprocess.py - read_granule() 方法
# 保留 CRS 变量（用于空间处理）
crs_vars = ['crs', 'spatial_ref']
for cv in crs_vars:
    if cv in ds and cv not in variables:
        variables = variables + [cv]
```

**经验教训**:
- SWOT NetCDF 文件使用 `grid_mapping` 属性关联 CRS 变量
- 读取数据时必须保留 CRS 相关变量，否则后续空间操作会失败
- CRS 信息通常存储在 `crs` 或 `spatial_ref` 变量的 `crs_wkt` 属性中

### 1.5 空间拼接策略

**问题描述**:
最初假设同一 pass 的多个 granule 需要拼接，尝试使用 `xarray.combine_by_coords()` 或 `combine_nested()` 失败，报错 "upside down rasters"。

**根本原因**:
- SWOT Raster 同一 pass 的 granule 在**空间上是分离的**（位于不同纬度带）
- 不同 granule 的 Y 轴方向可能不同（有的递增，有的递减）
- 这些 granule 本来就不是设计用来直接拼接的

**验证结果**:
```
Granule 1: Y 范围 3,860,000 ~ 4,010,000 (UTM)
Granule 2: Y 范围 4,860,000 ~ 5,010,000 (UTM)
# Y 坐标相差约 100 万米，说明是不同纬度带的独立 granule
```

**解决方案**:
改为**逐个处理 granule**，不进行空间拼接：

```python
# main.py - process_time_group() 方法
# 逐个处理granule，不进行拼接
# SWOT Raster 的同一pass的granule在空间上是分离的
for granule_path in granule_paths:
    ds = self.preprocessor.read_granule(granule_path)
    # 单独处理...
```

**经验教训**:
- SWOT Raster 每个 granule 是 128km × 128km 的独立网格
- 同一 pass 的多个 granule 覆盖不同的地理区域，而非同一区域的重叠观测
- 如果湖泊跨越多个 granule，需要分别处理后再聚合结果（而非预先拼接）

### 1.6 Y 轴方向处理

**问题描述**:
在手动拼接方法中，不同 granule 的 Y 轴方向不一致，导致数据对齐错误。

**解决方案**:
```python
# preprocess.py - _manual_mosaic() 方法
# Y轴可能需要翻转
if y[0] > y[-1]:  # Y递减（正常）
    y_start = np.searchsorted(-new_y, -y.min())
    y_end = y_start + len(y)
    data_aligned = data
else:  # Y递增（需要翻转）
    y_start = np.searchsorted(-new_y, -y.max())
    y_end = y_start + len(y)
    data_aligned = data[::-1, :]  # 翻转
```

**经验教训**:
- SWOT 数据的 Y 轴通常从大到小（北到南）
- 但某些 granule 可能相反，需要检测并处理

### 1.7 数据类型处理

**问题描述**:
在拼接数据集时，DateTime64 类型的变量（如 `illumination_time`）与 Float32 类型的变量混合，导致 xarray 操作失败。

**解决方案**:
```python
# preprocess.py - _manual_mosaic() 方法
# 确定数值型变量（排除时间、坐标等）
coord_vars = ['x', 'y', 'longitude', 'latitude', 'crs', 'spatial_ref',
              'illumination_time', 'illumination_time_tai']
numeric_vars = []
for var in datasets[0].data_vars:
    if var in coord_vars:
        continue
    dtype = datasets[0][var].dtype
    if np.issubdtype(dtype, np.number):
        numeric_vars.append(var)
```

**经验教训**:
- 拼接前需要区分数值变量和时间变量
- 时间变量需要特殊处理，不能简单地求平均

### 1.8 rioxarray clip 问题

**问题描述**:
`rioxarray.rio.clip_box()` 和 `rio.clip()` 方法可能因各种原因失败（坐标不匹配、几何问题等）。

**解决方案**:
实现备用手动裁切方法：

```python
# spatial_clip.py
def _clip_manual(self, ds: xr.Dataset, geometry) -> xr.Dataset:
    """手动裁切（备用方法）"""
    bounds = geometry.total_bounds
    if 'x' in ds.dims and 'y' in ds.dims:
        ds_clipped = ds.sel(
            x=slice(bounds[0], bounds[2]),
            y=slice(bounds[1], bounds[3])
        )
    ds_clipped = self._apply_geometry_mask(ds_clipped, geometry)
    return ds_clipped
```

**经验教训**:
- rioxarray 的 clip 方法在某些边界情况下不稳定
- 应始终准备备用方案

## 四、常见错误及排查

### 4.1 CRS 为 None

**错误信息**: `Cannot determine dataset CRS`

**排查步骤**:
1. 检查 `read_granule()` 是否包含 `crs` 变量
2. 检查 NC 文件中是否存在 `crs` 或 `spatial_ref` 变量
3. 检查变量是否有 `grid_mapping` 属性

### 4.2 裁切后无数据

**错误信息**: `valid_pixels < min_valid_pixels`

**排查步骤**:
1. 检查先验边界与数据边界是否有重叠
2. 检查坐标系统是否一致（UTM vs WGS84）
3. 检查 lake_id 是否正确匹配

### 4.3 几何错误

**错误信息**: `Geometry Collection not supported`

**排查步骤**:
1. 检查先验 Shapefile 是否有 GeometryCollection 类型
2. 使用 `geom.geom_type` 检查几何类型
3. 将复杂几何转换为 MultiPolygon

## 六、给 AI 助手的建议

1. **处理顺序：先 QC 后拼接**: 同一时间组的多个 Scene 先进行 QC，再空间拼接，最后裁切到湖泊

2. **相邻 Scene 有重叠**: 约 25-30km 沿轨重叠，使用平均值方法处理

3. **CRS 变量必须保留**: 读取数据时务必保留 `crs` 变量，合并后需要清理旧 CRS 并写入唯一 CRS

4. **跳过冰期过滤**: D 版本的冰标志无效，配置中设置 `skip_ice_filter: True`

5. **处理 None/NaN**: 在处理 geometry 字段前，始终检查是否为 None

6. **使用正确环境**: 运行 Python 脚本时使用 `conda activate py10`（或用户指定的环境）

7. **警告抑制**: 大量警告是正常现象，不影响处理结果

8. **进度监控**: 处理大量文件时，使用 tqdm 进度条和实时统计

9. **每个湖泊每天一条记录**: 确保处理流程正确，避免重复记录
